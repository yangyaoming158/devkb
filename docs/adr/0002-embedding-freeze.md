# ADR-0002：Embedding 模型与向量维度冻结

- 状态：已接受（2026-07-12）
- 依据：《模型与环境基准方案》预冻结决策规则 + `benchmarks/embedding_report.md` 实测数据

## 决策

**冻结 `Qwen/Qwen3-Embedding-0.6B`，向量维度 1024**。数据库 `chunks.embedding` 定为 `vector(1024)`，migration 001 据此编写（本 ADR 是该迁移的前置门禁，现已解除）。

## 关键数据（RTX 4060 8GB，语料=mini-mall 500 块，质量集=Eval v0 dev 15 问）

| 候选 | 维度 | Recall@5 | GPU 加载后显存(fp16) | GPU 吞吐 b32 | GPU 查询 P50 |
|---|---|---|---|---|---|
| **Qwen3-Embedding-0.6B** | 1024 | **0.80** | 1136 MB | 18.2 块/s | 30.4 ms |
| BAAI/bge-m3 | 1024 | 0.60 | 1083 MB | 46.3 块/s | 11.2 ms |
| BAAI/bge-base-zh-v1.5 | 768 | 0.467 | 391 MB(fp32) | 77.6 块/s | 6.0 ms |
| intfloat/multilingual-e5-base | 768 | 0.067（异常值，未深究） | — | — | 6.6 ms |

规则套用：Recall@5 差距 20pt > 5pt → 直接选质量最高者；淘汰线检查：加载 9.4s(<60s) ✓、加载后显存 1.14GB(<4GB) ✓、为 P2 reranker 共存留出 >6GB 余量 ✓。

## 使用约束（适配层必须实现，违反会 OOM 或掉召回）

1. **fp16 加载 + max_seq_length=1024**：fp32 + 长序列在 8GB 卡上实测 OOM。
2. **摄取批量 ≤32**：batch 64 时峰值显存实测 10GB（溢出到共享显存，性能悬崖）。
3. **前缀约定**：查询侧必须用模型自带 `prompt_name="query"`（指令前缀）；文档侧无前缀。适配层写单测锁定此约定。
4. **批量摄取需要 GPU**：本模型 CPU 批量编码不可用（同级 bge-m3 CPU 仅 0.7 块/s；Qwen3 CPU 轮 95 分钟未完成被中止）。CPU 模式仅可接受查询级低频编码。演示与开发环境要求宿主 GPU。

## 后果与放弃项

- 换模型 = 全量重嵌 + 迁移，故本决策进入冻结清单，翻案需新 ADR + 重跑基准。
- bge-m3（0.60）落选但记录在案：若后续发现 Qwen3 在真实使用中有系统性缺陷，它是第一替补（同维度 1024，切换不动表结构）。
- e5-base 的 0.067 为异常值（疑似 fp16/前缀交互），因远低于候选线未investigate，如实记录。
- 教训入库：首轮质量对比因抽样丢失锚点块而全体塌陷至 ≤0.40（天花板 6/15）。修复=锚点块强制保留 + 评测前先验证覆盖率，已固化进 `benchmarks/sample_corpus.py`。**任何检索评测先验证天花板再看数字。**
