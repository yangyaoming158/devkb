# ADR-0008：引用格式与 L0/L1/L2 校验分级

- 状态：已接受（2026-07-12 冻结；本文件为 T11.3 转写，内容以《范围冻结与架构决策》D8/D9 为准）
- 依据：《范围冻结与架构决策》D8/D9/C7/C9、《P0 实现规格》§6、《P1 Agentic RAG MVP 实现规格》§10、《Evaluation v1》§4.2/§5

## 背景

“给出了引用”不等于“引用存在”、“引文是原文”或“来源真的支持该结论”。这三类问题的可确定性和运行成本不同，必须分级，避免把 NLI 语义判断偷渡进在线路径。

## 引用身份与展示格式

- 每次 run 的 evidence 使用局部标识 `E1..En`；回答正文以 `[E#]` 引用，`E#` 必须能解析到本次 evidence 集中的真实 chunk。
- 对外引用保留 `chunk_id`、`rel_path`、`start_line/end_line`、`title_path` 和检索分数/排名信息；人类展示位置为 `rel_path:L{start}-L{end} · title_path`。路径、行号和标题路径继承 P0 契约，P1 只增不改。
- P1 `claims[]` 的每个事实性 claim 至少绑定一个 `evidence_id`，引文放在该 claim 的 `quotes[]` 中。
- 评测标注继续使用稳定的 `rel_path + anchor`，不把重摄取后可漂移的 `chunk_id` 写入数据集。

## 校验分级

### L0：引用存在性（P0 起，在线、确定性）

检查回答正文中的每个 `[E#]` 以及 P1 claim 的每个 `evidence_id`，必须属于本次 run 的 evidence 集。L0 不评估引文或 claim 的语义，只防止不存在或跨 evidence 集的编号被当成有效引用。

### L1：引文原文匹配（P1 起，在线、确定性）

每个 quote 经冻结的空白/标点规范化后，必须与对应 chunk 原文达到冻结阈值。规范化和阈值只能在 dev 数据上确定；逐字相同、空白/标点差异、轻微篡改、跨 chunk 拼接和错误 evidence 必须有正反例。L1 不改写语料原文和引用位置。

### L2：语义支持度（P2，仅离线 Evaluation）

L2 判断 claim 是否真被 evidence 语义支持。P0/P1 在线路径不使用 NLI、LLM judge 或冲突判定实现 L2；L2 推迟到 P2 离线评测，不参与 P1 实时控制流。

## 验证失败后的固定行为

1. 首次 L0/L1 失败时，向 `generate` 反馈机器可读错误，最多重生成 1 次；重生成消耗 ADR-0006 的全局供应商请求预算。
2. 第二次仍失败时，删除未通过的 claim；若剩余证据不足，确定性降级为 `partial` 或 `refusal`，并记录 warning。
3. 只有 L0/L1 违规能触发重生成。`evaluate` 的低信心、评测 proxy 或人工引用正确率不得在线额外增加 LLM 调用。
4. Evaluation v1 的 P1 Gate 要求最终 L0/L1 通过率均为 100%，但这是评测 Gate，不反向改变上述在线分级。

## 可追溯性与正确性的边界

引用只保证“系统能指回它使用的证据”，不保证该证据为真、完整或无恶意。语料内容和 evidence 始终是不可信数据：

- 同项目敏感内容可能被诱导写入回答，摄取期 secret 扫描/脱敏只能缓解，不保证完备；
- 恶意文档可以通过 L0/L1，因为它确实存在且引文与原文一致；
- 恶意链接、命令文本和其他注入内容仍可能进入回答或轨迹，需由输出层确定性标记/剥离和日志脱敏继续降低风险。

统一对外措辞是：**分层降低，不可消除**。
