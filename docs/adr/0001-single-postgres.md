# ADR-0001：单 PostgreSQL 与规模假设

- 状态：已接受（2026-07-12 冻结；本文件为 T10.0 转写，内容以《范围冻结与架构决策》D1/S1 为准）
- 依据：《范围冻结与架构决策》D1、审查处置 C5/S1

## 决策

**单 PostgreSQL 16 + pgvector 承担全部四类职责**：业务数据、向量检索、关键词检索（P1 起 FTS）、轨迹与评测数据。不引入 ES/Milvus/MinIO；Redis 推迟到 P2（在 P0/P1 无真实用途，compose 只保留 postgres）；P0–P2 不引入 Neo4j。

原规划的"五职责"含已推迟的 LangGraph checkpoint，修正为四职责（S1）。

## 前提：规模假设（超出即触发重新评估）

- 单项目 ≤ 10 万 chunks；
- ≤ 10 个项目；
- 单机部署。

在此规模下 pgvector 精确扫描/HNSW 均在可接受延迟内，单库运维成本远低于多存储组合；该假设未被验证的部分（真实 chunk 数、FTS 召回）列于源文档第五节"待验证假设"。

## 后果与放弃项

- P3 仅当 GraphRAG 对照评测显示稳定收益时，允许 Neo4j 作为 **sidecar** 引入；PostgreSQL 始终是文档、chunk、run、权限与引用的**真相源**（D1，ADR-0009 重申）。
- 换存储 = 迁移全部四职责数据，故本决策进入冻结清单，翻案需新 ADR。
