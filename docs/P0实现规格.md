## 1. 目标与范围

**目标**：一条可测、可复现、带真实引用的固定 RAG 链路：`Markdown 目录 → 分块入库 → 向量检索 → LLM 生成 → L0 校验 → 带路径/行号引用的回答`。

**P0 摄取范围**：mini-mall-order 的 `docs/**/*.md` + 根级 `README*.md`（约 50+ 文档，已是 Markdown，无需转换）。

**非目标**：Agent 环、LLM 规划、关键词/混合/RRF/rerank、代码/PDF/OpenAPI 解析、Redis、FastAPI、HNSW、拒答策略、eval harness 代码、增量索引、多用户。

## 4. CLI 契约（P0 唯一 API）

- `devkb ingest <目录> --project <slug>`：摄取；输出成功/失败/跳过计数与失败原因表；对未变文档重复执行零写入（幂等）。
- `devkb ask "<问题>" --project <slug> [--top-k 8] [--json]`：输出中文回答（引用以 `[E1]` 标记、英文术语保留）+ 引用表（`rel_path:L10-L42 · 标题路径`）+ token/延迟；`--json` 输出完整 Answer。
- `devkb runs list|show <run_id>`：查看历史 run 与 Answer JSON。

## 5. 数据库表（恰好 4 张）

- `projects`：id, slug(unique), name, created_at。
- `documents`：id, project_id(FK,NN), rel_path, title, doc_type('markdown'|'text'), content_hash, status('active'|'failed'), parse_error, created_at, updated_at；unique(project_id, rel_path)。
- `chunks`：id, project_id(FK,NN), document_id(FK), ordinal, title_path, content, content_hash, token_count, start_line, end_line, `embedding vector(<ADR-002 冻结后填>)`, created_at；索引 btree(project_id, document_id)；**不建 HNSW**（小语料精确扫描，召回=100%）。
- `agent_runs`：id, project_id(FK,NN), question, answer(JSONB), model, tokens_in, tokens_out(合计值，便于查询), **usage(JSONB——供应商原始 usage，含 prompt_cache_hit_tokens/prompt_cache_miss_tokens 等分档字段，计价与复算以此为准)**, cost(numeric 可空——按三档单价分别计算：缓存命中输入/未命中输入/输出，见 ADR-0004), latency_ms, status, created_at。（usage/三档计价为 2026-07-13 第三轮审查修正：DeepSeek 按缓存命中与否分别计价，仅存合计 tokens 无法复算）

没有 sources/revisions/ingest_jobs/steps 表——P0 无对应需求。

## 6. Chunk 结构与引用格式（P0 冻结，P1 只增不改）

Chunk：`{id, project_id, document_id, ordinal, title_path("架构 > 库存 > 并发控制"), content, content_hash(sha256), token_count(冻结模型 tokenizer 计), start_line, end_line, embedding}`。

token 计数接缝（2026-07-12 两轮外部审查后定稿）：分块器注入**普通 callable**（`Callable[[str], int]`）——不新增 Protocol（CLAUDE.md 硬规则：Protocol 仅允许出现在 embedding.py 与 llm.py）。三种注入：① 生产=冻结模型 tokenizer（懒加载，属 ml 组）；② CI 与默认 golden 测试=确定性近似计数器，产出**快照 A**（锁 chunk 边界/行号/title_path/近似 token_count）；③ 本地 ML 测试（CI 自动跳过）=真实 Qwen tokenizer，产出**独立快照 B**（锁真实 token_count 与该模式下的 chunk 边界）。不做误差范围断言（脆弱且无行动价值）。

Answer JSON：

```
{ "answer_text": "……[E1]……[E2]",
  "citations": [ { "evidence_id": "E1", "chunk_id": "...", "rel_path": "docs/architecture.md",
                   "start_line": 120, "end_line": 158, "title_path": "…", "score": 0.83 } ],
  "warnings": [],
  "stats": { "tokens_in": 0, "tokens_out": 0, "latency_ms": 0, "model": "deepseek-…" } }
```

L0 规则：answer_text 中每个 `[E#]` 必须属于本次证据集合；越界引用剔除并记入 warnings。生成 prompt 要求"仅依据证据作答，证据不含答案时明确说明"——P0 诚实性仅到 prompt 级（确定性拒答是 P1 内容，此为已知限制）。

## 7. 摄取流程（同步、逐文档隔离失败）

扫描（仅 .md/.txt，单文件 ≤5MB，跳过隐藏目录）→ 编码规范化（charset-normalizer → UTF-8）→ 文档 content_hash 比对，未变跳过 → markdown-it-py 标题树分块（目标 300–500 token，段落递归切分，代码围栏不切，title_path 注入，记录源行号）→ 单文档事务内删旧插新 → 批量嵌入（batch 取基准值，OOM 减半退避）。失败：status='failed' + parse_error，继续下一文档。

## 8. 检索流程

查询嵌入 → `WHERE project_id=<repo 绑定> AND 所属文档 status='active' ORDER BY embedding <=> :q LIMIT k`（精确扫描）→ chunk + 余弦分数。无融合、无重排、无阈值门（P1 加）。（status 过滤为 2026-07-15 用户裁决补入：active 文档更新失败时旧 chunks 因事务回滚保留，不过滤会引用与当前文件行号不符的陈旧内容，见任务清单偏差记录。）

## 9. 异常与配置

`DevKbError` → `ConfigError` / `IngestError`(→`ParseError`,`UnsupportedFileError`) / `EmbeddingError` / `LLMError`(→`LLMTimeoutError`,`LLMResponseFormatError`) / `NotFoundError`。CLI 顶层统一捕获渲染，非 0 退出码。

配置（env，前缀 `DEVKB_`）：`DATABASE_URL`、`LLM_BASE_URL`(DeepSeek)、`LLM_API_KEY`、`LLM_MODEL`、`EMBEDDING_MODEL_ID`、`EMBEDDING_DEVICE(cuda|cpu)`、`EMBEDDING_BATCH_SIZE`、`CHUNK_TARGET_TOKENS`、`RETRIEVAL_TOP_K`、`LOG_LEVEL`、`APP_ENV(dev|test)`。

## 10. 测试与 CI

- 单元：分块器 golden 测试（fixture md → chunk 结构快照含行号）、L0 引用解析、content_hash 稳定性、config。
- 集成（compose 真 PG；用 **FakeEmbedder** 确定性哈希向量——测机制不测模型质量，CI 无需 GPU）：摄取计数与幂等（二次摄取零新增）、已知查询命中期望 chunk、**双项目隔离断言**、runs 落库。
- E2E（FakeLLM）：ask 全链路；含"FakeLLM 输出虚假 E# 被 L0 剔除"用例。
- CI：ruff → pyright → 单元 → 集成（pgvector service container）→ 隔离静态扫描（sqlalchemy 查询仅限 repositories 模块）。真实模型与 API 不进 CI。

## 11. Docker Compose

单服务 `pgvector/pgvector:pg16` + 健康检查 + 命名 volume + init 建扩展。应用与模型跑在宿主 WSL（GPU 直用）。

## 12. 验收标准（全部可命令/测试验证）

1. `docker compose up -d && uv run alembic upgrade head` 成功。
2. `devkb ingest`（mini-mall docs 目录）输出统计；**重跑第二次新增为 0**。
3. 人工抽查 5 问：每答 ≥1 条引用，`rel_path:start_line-end_line` 打开后内容与引用对应。
4. e2e 测试证明虚假 E# 被 L0 剔除。
5. `pytest` 本地与 CI 全绿；ruff/pyright 零错误。
6. 双项目隔离集成测试通过。
7. `devkb runs show` 可取回含 token/延迟的历史 run；至少 1 条真实 run 的 cost 非空且可由 usage×已记录单价复算（防止全 NULL 过验收，2026-07-12 审查补强）。
8. `benchmarks/` 有基准报告，`docs/adr/` 有 ADR-001~004、007。

## 13. 风险

① 冻结模型中英混合质量不达预期（缓解：基准含质量小测）；② DeepSeek 结构化输出/延迟波动（T1 smoke 暴露）；③ WSL 下 CUDA torch 安装波折（基准第 0 步暴露）；④ 扁平结构 P1 需一次目录重构（已接受，换 P0 简单性）。
