## 过程纪律（自 P0–P1.5 实测教训写入，本阶段起具约束力）

以下每条都对应一次真实返工，不是形式要求：

1. **packet 里的每个数字必须来自跑过的探针**（`WF-P3-09`）。散文里的每个「因为…所以…」「这条输入会走那条分支」「这份落盘数据长这样」，旁边必须有一行可复现的命令与关键返回值，或**显式标注「未验证的假设」**。T31.2R-d/R-e 因同型失实各触发一次 `RETURN_TO_DESIGN`。
2. **交付物主体是测试装置的任务，前审有结构性盲区**（`WF-P3-11`）。若某任务的产出几乎全是测试装置、且装置测的是**尚未写出的代码的性质**，实现前审查无法认证它——此类任务须先写可运行的最小装置骨架跑通，再据实际运行结果冻结测试矩阵。T31.2R-e 五轮前审、生产代码零改动后被撤销。
3. **推送后必须用 `git ls-remote origin <branch>` 与本地 HEAD 逐字比对。** 在 task 分支上提交后直接 `git push origin p1.6` 推的是**本地 p1.6**（未合并），是空操作且不报错。2026-08-09 曾据此险些误报「已推送、CI 全绿」（同类流程缺口见 `WF-P3-02`）。
4. **「本轮无样本触发」不得记为通过**（《P1.6实现规格》§12.1）。每条 Gate 必须同时报告施压样本数；为 0 时记「未施压」，既不通过也不失败。
5. **机器可判定子集全绿 ≠ 判据达成**（同上）。含命题级内容的判据必须声明「机器覆盖到哪、剩下的归谁判」，并把未覆盖部分路由到 U4.2。
6. **冻结记录只允许朝不利方向如实修正**，不允许朝有利方向自行修订；反向情形必须重新提请用户裁决。

  - ⚠️ 本项触碰既有摄取管线与 chunk 关联，**必须有 P0/P1/P1.5 摄取回归全绿**才算完成
- [ ] T34.4 联合对账 + 原子发布
  - 判据：发布前三项对账全过才可 `ready`——① `documents` active 路径集合 == manifest 入选路径集合；② 每条 `source_sha256` 与 manifest 一致（**只比 `source_sha256`，绝不比 `content_hash`**）；③ inventory 的 `snapshot_id` 覆盖面与 `documents` 一致。任一不过即 `failed` 并记差集；**发布 = 单事务内把 project 的 `current_ready_snapshot_id` 指针切到新快照**；失败则指针不动、旧 ready 数据完好
  - 📌 **删除对账在此退化为结构性质**：新快照的路径集合就是 manifest 入选集合，天然不含已删除文件——不需要任何"清理旧 active"的过程性步骤
- [ ] T34.5 查询侧：ready 解析 / 单 run pinning / 启动恢复 / provable 降级
  - 判据：问答在 run 开始时解析一次 `current_ready_snapshot_id` 并在本 run 内**固定不变**；残留 `building` 在下次摄取或服务启动时置 `failed`；**`provable` 标志按 §4.2.5 计算**（manifest v2 ∧ 校验通过 ∧ 对账全过 ∧ 源工作树干净）；`provable=false` 时只允许正向查询、proof `verdict` 上限 `unavailable`
  - ⚠️ **裸目录摄取继续支持、行为逐字不变**（`tests/integration/test_ingest.py` 依赖它），只是产出的快照 `provable=false`。**这不是契约变更**——早期草案写的「manifest 缺失即拒绝摄取」会静默破坏既有合同，且与同节的「仍可正向查询」自相矛盾，已废止
