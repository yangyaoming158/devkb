## 过程纪律（自 P0–P1.5 实测教训写入，本阶段起具约束力）

以下每条都对应一次真实返工，不是形式要求：

1. **packet 里的每个数字必须来自跑过的探针**（`WF-P3-09`）。散文里的每个「因为…所以…」「这条输入会走那条分支」「这份落盘数据长这样」，旁边必须有一行可复现的命令与关键返回值，或**显式标注「未验证的假设」**。T31.2R-d/R-e 因同型失实各触发一次 `RETURN_TO_DESIGN`。
2. **交付物主体是测试装置的任务，前审有结构性盲区**（`WF-P3-11`）。若某任务的产出几乎全是测试装置、且装置测的是**尚未写出的代码的性质**，实现前审查无法认证它——此类任务须先写可运行的最小装置骨架跑通，再据实际运行结果冻结测试矩阵。T31.2R-e 五轮前审、生产代码零改动后被撤销。
3. **推送后必须用 `git ls-remote origin <branch>` 与本地 HEAD 逐字比对。** 在 task 分支上提交后直接 `git push origin p1.6` 推的是**本地 p1.6**（未合并），是空操作且不报错。2026-08-09 曾据此险些误报「已推送、CI 全绿」（同类流程缺口见 `WF-P3-02`）。
4. **「本轮无样本触发」不得记为通过**（《P1.6实现规格》§12.1）。每条 Gate 必须同时报告施压样本数；为 0 时记「未施压」，既不通过也不失败。
5. **机器可判定子集全绿 ≠ 判据达成**（同上）。含命题级内容的判据必须声明「机器覆盖到哪、剩下的归谁判」，并把未覆盖部分路由到 U4.2。
6. **冻结记录只允许朝不利方向如实修正**，不允许朝有利方向自行修订；反向情形必须重新提请用户裁决。

## P1.6 验收总清单

对《P1.6实现规格》§12.1 的 **G1–G12 判定表**逐条核对。**每条回填三样：谓词结果（True/False/None/未施压）、分子分母或施压数、证据链接**；含人工残余的条目还须回填 U4.2 的对应结论。

- [ ] **G1** 符号定位：正例题 proof `verdict=found` ∧ `locations` 非空 ∧ 均在快照 manifest 内 ｜ 人工残余 → U4.2 §符号正例
- [ ] **G2** 零编造符号：所有被点名符号的 `subject_origin ∈ {user_question, retrieved_evidence, inventory}` ｜ 结构可判、无残余
- [ ] **G3** refs 不绑错：`refs` ⊆ 该 proof 的 `locations`；经确认者 `basis ≠ corpus_index` ｜ 人工残余「该位置是否真是所述命题的实现」 → U4.2 §refs 抽查
- [ ] **G4** 论域外不否定：论域外主体 `verdict ∈ {out_of_scope, unavailable}`，**恒不为 `not_found`** ｜ 结构可判
- [ ] **G5** 证明四要素完整：`verdict=not_found` 者 `complete=true` ∧ `truncated=false` ∧ 六项披露非空
- [ ] **G6** 子循环有界：每 run 总请求 ≤11 ∧ 子循环 ≤5 ∧ 轮次 ≤4；证据充分题轮次 =0；`policy_refusal` 题工具调用 =0
- [ ] **G7** 预算守卫：冻结用例证明「剩余预算 < `GENERATE_RESERVE` 时立即结束子循环」且终态 `mode ∈ {full, partial}` ∧ `claims` 非空 ∧ L0/L1 通过
- [ ] **G8** 安全边界：静态扫描（工具白名单外零调用点、`project_id` 不在任何 schema、零 subprocess/写操作）+ 冻结测试（非法参数不到达 Repository）+ 工具失败零重试
- [ ] **G9** refine 符号约束：refine 输出符号 token ⊆（用户问题 ∪ 证据 ∪ inventory 命中）；遍历/执行类动作被拒绝并记 warning ｜ 人工残余「范围是否被扩大」 → U4.2 §refine
- [ ] **G10** v1.5 无退化：按 §12.2 预登记的基线报告与指标键逐键比较；**任一键 `None` 则整条 `None`**；**退化即 `False`，「已如实说明」不构成豁免**
- [ ] **G11** 门禁全绿：本地 `make ci && make eval-ci` 零失败 ∧ 头提交 Actions `success`（`head_sha` 与本地 HEAD **逐字比对**）∧ `PROMPT_VERSION` 递增已记录
- [ ] **G12** v1.6 holdout：预登记的 holdout 契约聚合为 `True` **且施压样本数 > 0**；只运行一次、不据结果调参。**未运行记「未达成」，不是 `None`**

> **通用规则**：分母为 0 → 记「**未施压**」，既不通过也不失败；任何键 `None` → 不计入通过；含命题级内容者必须指明人工残余去向。
>
> ⚠️ **G12 的严格度是一处待你确认的取舍**：审查者给了两个选项——(A) holdout 契约聚合须为 `True` 才算通过（本稿采用），(B) 把 holdout 移出「P1.6 通过」条件、改为纯证据任务。采用 (A) 的理由是「跑一次就算」没有判别力，而 P1.5 已有「Gate 未通过也如实冻结」的可行先例；代价是单次随机运行可能卡住整个阶段。**若你认为过严，改 (B) 即可，本行留待裁决。**

**明确不作为 P1.6 出口**（属 P1.7/P2）：`.vue/.ts/.sql` 已摄取、检索指标提升、`claims` 与正文一致、在线 L2。**P1.6 通过只证明「仓库级确定性事实可查、可证、可界」，不得对外宣称检索质量或语义正确性有提升。**
