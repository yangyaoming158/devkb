## 过程纪律（自 P0–P1.5 实测教训写入，本阶段起具约束力）

以下每条都对应一次真实返工，不是形式要求：

1. **packet 里的每个数字必须来自跑过的探针**（`WF-P3-09`）。散文里的每个「因为…所以…」「这条输入会走那条分支」「这份落盘数据长这样」，旁边必须有一行可复现的命令与关键返回值，或**显式标注「未验证的假设」**。T31.2R-d/R-e 因同型失实各触发一次 `RETURN_TO_DESIGN`。
2. **交付物主体是测试装置的任务，前审有结构性盲区**（`WF-P3-11`）。若某任务的产出几乎全是测试装置、且装置测的是**尚未写出的代码的性质**，实现前审查无法认证它——此类任务须先写可运行的最小装置骨架跑通，再据实际运行结果冻结测试矩阵。T31.2R-e 五轮前审、生产代码零改动后被撤销。
3. **推送后必须用 `git ls-remote origin <branch>` 与本地 HEAD 逐字比对。** 在 task 分支上提交后直接 `git push origin p1.6` 推的是**本地 p1.6**（未合并），是空操作且不报错。2026-08-09 曾据此险些误报「已推送、CI 全绿」（同类流程缺口见 `WF-P3-02`）。
4. **「本轮无样本触发」不得记为通过**（《P1.6实现规格》§12.1）。每条 Gate 必须同时报告施压样本数；为 0 时记「未施压」，既不通过也不失败。
5. **机器可判定子集全绿 ≠ 判据达成**（同上）。含命题级内容的判据必须声明「机器覆盖到哪、剩下的归谁判」，并把未覆盖部分路由到 U4.2。
6. **冻结记录只允许朝不利方向如实修正**，不允许朝有利方向自行修订；反向情形必须重新提请用户裁决。
