## T22 证据类型硬约束与权威性分层（RT-01/05）

- [ ] T22.1 required-evidence 结构化模型
  - 确定性代码从用户问题解析被明确要求的证据类型/路径（生产源码/配置/迁移/引用某类/测试等），构造 required-evidence 清单；plan/evaluate 结构化输出增加逐项覆盖状态字段（不新增在线调用点）
  - 判据：schema 严格 Pydantic、`PROMPT_VERSION` 递增并快照；解析以确定性规则为主，plan 只可回显确认且每个 required 项须锚定问题原文片段，LLM 不能覆盖或伪造 required 清单；解析对"请引用 X 与 Y""不要用测试代替实现"等表述有确定性单测；解析规则不得只针对回归集单句特判，须过"自然问法"反例
- [ ] T22.2 full/sufficient 逐类硬约束
  - 判据：每个必需证据类型都有直接匹配引用才允许 `full`；缺任一必需类型时确定性最高判 `partial`；测试/设计/dev-log 不占用必需生产证据预算；Fake 矩阵覆盖"仅测试代替生产→不得 full""必需类型齐全→可 full"
- [ ] T22.3 权威性分层
  - 判据：区分 current docs / production source·config / tests / historical plans·audits / dev-log；规划材料只支撑"规划过/范围状态"、不支撑"已实现"；分层规则有单测；具体权重变更须经 Evaluation-v1.5 对照，不凭个案

## T23 not_found 四分类与事实校验（RT-02/15）

- [ ] T23.1 四分类枚举与三类实现
  - 判据：枚举 `missing_from_current_evidence`/`unsupported_or_not_ingested`/`confirmed_undocumented`/`forbidden_or_unavailable_by_policy`，以 Answer JSON 平行字段 `not_found_details` 承载（`not_found` 保持 `list[str]`，见规格 §2）；P1.5 实现前二类 + 策略类（后者见 T27）；`unsupported_or_not_ingested` 由 `SUPPORTED_SUFFIXES` + documents 表确定性判定（含有限且单测覆盖的技术词→后缀映射表），措辞用条件式、不得断言仓库有无该文件（仓库级普查属 P1.6）并有单测；`confirmed_undocumented`/全局不存在需 inventory，P1.5 不得断言，降级为"当前证据不足以穷举确认"

## T27 policy-refusal 终态（RT-22）

- [ ] T27.1 前置识别与独立终态
  - 判据：明确索取系统 Prompt/凭据/隐藏文件内容或要求越权执行命令的请求，在检索潜在敏感语料与调用任何工具之前返回独立 `policy_refusal`（mode 第四枚举值，见规格 §2）；识别 = 确定性规则前置（命中零 LLM 调用）+ plan policy 标志兜底（不新增调用点，retrieve 前短路）；照常落一个终态 `policy_refusal` 的 run（零 tool invocation、记录触发层 rule/plan）以保可审计；固定无秘密文案；不检索、不生成、不执行、不编造；受保护对象不得写入普通 `not_found`
- [ ] T27.2 召回率与误杀反例
  - 判据：用多种攻击改写、直接索密、角色覆盖、文档内注入、要求编造/执行命令验证召回；用合法安全咨询（"如何保护 API key"）与普通 `.env.example` 文档题验证不误杀；分别报告泄露率、越权工具调用、策略漏拦与误杀
