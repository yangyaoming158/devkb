# devkb 路线图 v2

> 状态：已接受的方向级路线（ADR-009）  
> 生效日期：2026-07-14  
> 执行约束：P0 已于 2026-07-16 复验通过，当前只执行 P1；每个后续阶段必须等前一阶段验收后再创建实现规格和任务清单。
> 关系：本路线图取代《项目初步规划报告》的 P2+ 优先级，不取代 P0/P1 冻结范围。

## 1. 路线目标

用一条可分段验收的路线，把 devkb 从固定 RAG 基线推进到可投递的 Python Agentic RAG 项目，再按面试反馈选择云部署、低代码集成、Multi-Agent 和 GraphRAG，避免把“开始投递”绑定到所有进阶能力完成。

核心顺序：

```text
P0 基线
  → P1 Agentic RAG MVP
  → P2-A LangFuse
  → P2-B MCP
  → 包装与投递
  → P2-C 投递后增强（逐项选择）
  → P3 Multi-Agent/GraphRAG（评测收益成立才进入）
```

## 2. 估时口径

- 估时按单人每周约 15–20 个有效开发小时、依赖和账号可用计算；是容量级别，不是承诺日期。
- “半周”约 8–10 小时，“一周”约 15–20 小时，“两周”约 30–40 小时。
- 估时包含代码、测试、评测、文档和一次演示验收，不包含等待 API/云账号审批、模型下载和不可控网络故障。
- Gate 未通过时优先修复，不为了赶估时勾选；实际状态只写入当前阶段任务清单。

## 4. 各 Gate 的最小证据

### G0：P0 可运行基线

范围和验收完全以 `docs/P0实现规格.md`、`docs/P0任务清单.md` 为准，本路线图不增加任务。

最小证据：真实语料摄取与幂等、向量检索、DeepSeek 引用回答、虚假引用 L0 处理、run/cost 落库、隔离测试、CI、人工抽查报告。

### G1：P1 Agentic RAG MVP

范围完全以《范围冻结与架构决策》的 P1 行为边界和 P0 验收后创建的 P1 规格为准。

最小证据：

- LangGraph `plan→retrieve→evaluate→refine(≤1)→generate→verify→finalize`；
- Hybrid/RRF 相对纯向量的对照结果；
- 不可答拒答、引用 L1、循环上限、工具故障降级；
- agent_steps/tool_invocations 可回放；
- FastAPI 最小接口与 Evaluation v1 回归门。

**禁止口径**：G1 是 Agentic workflow，不自动等于 Multi-Agent。

### G2：LangFuse 最小闭环

最小证据：

- run_id 能关联本地 run 与 LangFuse trace；
- graph node、retrieval、LLM call 有 span/generation；
- 模型、Prompt 版本、tokens、cost、latency、错误与质量 score 可查；
- 至少一次 dataset 基线与变更后对照 run；
- 观测不可用时主链路降级，测试不访问真实服务；
- 正文、secret 和不必要源码不上传。

### G3：MCP 只读 Server

最小证据：

- 至少 3 个有真实用途的只读工具和 1 个 resource；
- MCP Inspector 或真实客户端完成发现与调用；
- 复用 Repository/project_id 隔离；
- 覆盖跨项目越权、非法 chunk、超长输入、返回上限、超时和服务失败；
- 不存在写文件、执行命令、任意 URL 抓取或数据库写工具；
- MCP 调用可关联本地 tool invocation 与 LangFuse trace。

### G4：投递包

必须包含：

- 一页式快速启动 README；
- 当前真实架构图与 Agent 状态图；
- 模型/检索/拒答/引用/故障样本评测报告；
- 5–8 分钟可重复演示脚本与备份截图；
- 简历项目描述和面试口径，明确已实现/未实现边界。

G4 通过后的简历可以写“提示词设计与上下文管理实践”，不能写“Context Engineering 对照实验”；后者需 G8。

### G5：教育场景适配

最小证据：10–20 份自编或许可清晰 Markdown、10 道可回答题、3 道不可答题，独立 project_id，复用同一链路并通过隔离与引用检查。不得使用学生 PII 或把演示包装成客户项目。

### G6：单实例云演示

最小证据：一个云平台/区域/实例、受控访问或 HTTPS、Secret 注入、`/healthz`、结构化日志、CPU/内存/磁盘/可用性基本指标，以及从干净环境重新部署的记录。

明确不是 Gate：K8s、HA、多区域、自动扩缩、正式备份体系、恢复演练、完整灾备、生产 SLA。

### G7：n8n 集成

最小证据：一个真实外部事件工作流，例如文档变更 webhook → ingest → 状态查询 → 触发评测 → 失败通知；导出可复现 workflow JSON。n8n 不实现 RAG 或 Agent 核心逻辑，不同时引入 Dify。

### G8：Context Engineering 与多模型对照

先固定数据集和评测指标，再单变量比较：

- system/developer 指令与证据数据边界；
- 上下文选择、排序、去重、压缩和 token budget；
- Prompt 版本、结构化输出和失败降级；
- 至少两个模型/模式的质量、结构化成功率、延迟和成本。

只有报告可复现且结论进入配置/Prompt 决策，才可写“Context Engineering（含对照实验）”。

### G9：LlamaIndex 受控实验

只在 `benchmarks/` 或 `experiments/` 对同一语料做一种摄取/检索对照，比较质量、延迟、可控性与迁移成本。不得替换 `LLMClient`、`Embedder`、Repository 或默认检索路径。

### G10：原 P2 能力池

Reranker、增量索引、冲突检测、额外解析类型、离线 NLI 等逐项提出假设、建立基线、单独裁决；无收益或演示价值不足就保留负结果并停止。Redis、SSE、JWT/RLS 不因旧路线出现而自动进入。

### G11–G12：GraphRAG

G11 先产生 Hybrid 失败问题集和关系 schema 候选。G12 才允许构建 Neo4j sidecar，使用同一问题集比较答案正确性、引用支持度、延迟、成本和索引开销。无稳定收益不并入默认栈；PostgreSQL 始终是真相源。

### G13：Multi-Agent

至少两个 Agent 的职责、工具或上下文明显不同，建议从 Vector Retrieval、Graph Retrieval、Evidence Critic 中选择，由 supervisor 调度/汇总。必须与 G1 单 Agent workflow 对照质量、token、延迟和失败率；无收益不进入默认路径。

## 7. 裁剪规则

时间不足时从后向前裁剪：LlamaIndex → n8n → 云部署 → GraphRAG → Multi-Agent → 缩小教育语料。P1、LangFuse 最小闭环、MCP 只读 Server 和投递包不裁剪，它们构成 G4 可投递线。

任何 Gate 都允许得出“收益不足，不进入默认栈”的负结论；有完整基线、实验和停止决策即是有效工程结果，但不能在简历中写成已上线能力。
