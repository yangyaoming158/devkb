### Gate 架构（**第四次修订**，代码审查 T311-CR-01 判 `RETURN_TO_DESIGN` 后重建）

首版把 `all_hard_gates_passed` 定成 12 个冻结键的合取，而 fail-fast 探针只进 section gate——安全分节 `False` 时总判定仍可为 `True`，「任一分节失败不得被掩盖」这条唯一核心验收**当场不成立**（实测可复现）。用户 2026-08-03 裁决重建方案 **A：section 为权威 + 补第 13 键**：

```
sections[k]["gate"]      ← 权威结果：由该节的源可观察量算出，取该节全部具名键的三态合取
gate_summary             ← 13 个具名键，是 section 内同一批结果的**投影**（只引用，不另起判定）
all_hard_gates_passed    = all(sections[k]["gate"] is True for k in SECTION_KEYS)
```

| section | 归属的具名硬键 |
|---|---|
| `retrieval` | `retrieval_no_regression` |
| `evidence_selection` | `zero_full_without_required_evidence` |
| `claim_support` | `l0_l1_all_pass`（§7 硬 Gate + §14「L0/L1 继续全绿」，不属 §5.1 九条） |

| `safety_reliability` | `policy_terminal_correct`、`budget_and_terminal`、**`fail_fast_isolation_ok`（新增第 13 键）** |

`fail_fast_isolation_ok` 的来源是《Evaluation-v1.5》**§5.2 第 8 条**而非 §5.1 九条，报告与 packet 均须逐字标注这一区别，不得让读者以为 §5.1 有十条。它进 `gate_summary` 是为了**在两处都不隐形**：section 合取会捕获它，具名键让报告读者直接看见它。

**恒等式必须机器锁定**：`all(sections[k]["gate"] is True) ⟺ all(gate_summary[j] is True)`——两者是同一批数字的两种视图，任何一侧漂移都意味着有键脱离了 section 或有 section 结果没进键。

**U14 必须能证伪重复归属（第五次修订，RD-CR-01）**：单靠上面这条合取恒等式不行——`x ∧ x = x`，一个键被两个 section 同时认领时两侧仍然相等，随机三态组合也照样全绿。U14 改为断言两件事：①把 section→键映射**展平后取 `Counter`，须恰等于 `{每个键: 1}`**（同时排除遗漏与重复归属）；②对每个键**确定性地**跑单 `False` 与单 `None`，验证「section 合取 ⟺ 13 键合取」。不再用随机化组合。

**端到端接线要求（第五次修订，RD-CR-01）**：第四次修订要求「13 键 × {坏源值, 不可测量} = 26 组，每组其余 12 键逐字不变」——**该矩阵不可执行**：真实评分对每条成功 row 同时产出 consistency / L0-L1 / G4b / 必需证据四类观察量，它们共用 `measured=bool(succeeded)`，「无成功 row」会让这一整组**同时**变 `None`，任何一个都无法单独变 None 而其余不动。改为按 `None` 的**可达性**分三层：

- **L1 坏源值（13 组，全部可独立构造）**：从 `Answer` JSON / run trace / 预登记行出发，经**真实 `score_*` 纯函数**产出 row 再进聚合。每组断言四层：①`sections[k]["gate"] is False`；②该具名键 `is False`；③`all_hard_gates_passed is False`；④**其余 12 键逐字不变**。
- **L2 可独立构造的 `None`（8 组）**：`retrieval_no_regression`（不传报告）、`policy_terminal_correct`／`global_negation_honest`／`uningested_disclosed`（**保留成功 row，只去掉该具名子集的题**）、`contract_expectations_met`／`extended_expectations_met`（**保留另一 kind 的成功 row**）、`zero_absence_assertion_on_known_paths`（有成功 row 但可判定语段为 0）、`fail_fast_isolation_ok`（不传探针）。这 8 组各自**只让目标键变 `None`**，断言同上四层，其余 12 键逐字不变。
- **L3 空 rows 的联动 `None`（1 组，11 键联动）**：`rows == []` 时三组键**同时**变 `None`——①共用 `measured=bool(succeeded)` 的 **4 键**（`consistency_all_true`／`l0_l1_all_pass`／`zero_full_refusal_with_direct_evidence`／`zero_full_without_required_evidence`）；②依赖题目子集的 **6 键**（`contract_expectations_met`／`extended_expectations_met`／`zero_absence_assertion_on_known_paths`／`policy_terminal_correct`／`global_negation_honest`／`uningested_disclosed`）；③`budget_and_terminal`，其可测性是 `bool(rows)`，**只在空 rows 这一种情形下**与前两组重合。共 **11 键**，只有来自独立源的 `retrieval_no_regression`（仍传合格报告）与 `fail_fast_isolation_ok`（仍传隔离成功探针）保持 `True` 不变。**作为一组**断言「空 rows ⟹ 这 11 键同时 `None` ∧ 另 2 键逐字不变 ∧ 总判定 `False`」。
  - **必须用空 rows，不得用 failed rows 凑「零成功」**：`budget_and_terminal` 的可测性冻结为 `bool(rows)`，非空 failed rows 下它**已被测量**且因 `no_failed_runs` 不成立而得 `False`——不是 `None`（该形态由 I2 锁定，不属本层）。这条同时说明为什么①那 4 键的 `None` 也只能靠空 rows 到达：任何非空 failed rows 都会把 `budget_and_terminal` 从 `True` 变成 `False`，破坏「其余键逐字不变」。
  - **如实登记边界**：上述 11 键里，②那 6 个子集依赖键的 `None` 已在 L2 单独构造过；剩下 **5 键（①的 4 键 + `budget_and_terminal`）的 `None` 在源端不可单独构造**——注意两者机制不同：4 键是因为共用 `measured=bool(succeeded)` 而彼此绑死，`budget_and_terminal` 是因为 `measured=bool(rows)` 使其 `None` 唯一出现在空 rows 场景、必然与其余 10 键同时发生。本 packet 不假装这 5 键各自独立，改由**独立的三态 reducer 单测 U10r** 覆盖 `_conjunction` 与 `all_hard_gates_passed` 的逐组合行为，且 U10r 明示自己只测 reducer、不冒充源端接线。

合计 **22 组**（13 + 8 + 1）。**明令禁止两种写法**：①`gate_summary[key] = …`（只证明最终 reducer）；②覆盖已评分 row 的中间字段（如 `evidence_selection.evidence_backed_aspect`，绕过评分函数）——首版 U10 正是后者，M3 变形据此存活。

**`split_assertion_segments` 冻结规则**（第三次修订，PG-T311-04：原先只有函数名，U-B4f 无法唯一实现）：

1. 切点字符：中文句末标点 `。` `！` `？` `；` 与换行 `\n` **无条件**成为切点；

3. 括号内不切：按 `（）` `()` `【】` `[]` 计深度，深度 > 0 时忽略上述切点（与 `not_found._bracket_depths:567` 同型）；
4. 切后逐段 `strip()`，丢弃空段；
5. **不做大小写折叠、不做 NFKC**——路径匹配用 `path_matches_token`（大小写敏感），否定短语全为中文不受影响。两侧口径必须一致，否则 `RagService` 与 `ragservice` 会给出不同判定。

### 异常与恢复流

- 单题异常 → `status="failed"` + 错误类型，继续下一题；G9 判 False。
- e08（`expected_mode_p15 == "not_found_404"`）**从问答循环分出**：其 API 契约（404 + `NOT_FOUND`）由既有 `tests/integration/test_api.py:167` 承担（m16 断言 4），本任务**引用而不重写**；harness 另跑一次进程内跨 project `get_run_trace` 探针，**只断言它抛 `NotFoundError`（`cross_project_isolation`）**。**探针不读任何表计数**（第五次修订，RD-CR-03）：三个 run/step/tool 仓储都没有 count 方法，D7 又禁止在本模块构造查询、`repositories.py` 不在范围，故按用户 2026-08-03 裁决删除该声明；「零持久化副作用」这条断言**唯一**由 I8 在真实 ASGI 请求上承担，报告里 `fail_fast` 节标 `measured_in: "deterministic_layer"` 并逐字给出 I8 出处。首版把 `counts_unchanged` 硬写成 `True` 且一次计数都没读（T311-CR-03）。
- `CorpusProfile.known is False` 或 `truncated is True` → 依赖 corpus 的判定整体进 `undecided`，**绝不因此判「已索引」或「未索引」**。
- `--retrieval-report` 文件不存在/非 `p1-eval-v1.x`/**六项**校验不过 → 前两者抛 `InvalidInputError`（"忘了传"与"传了坏文件"必须可区分），后者落 `measured=True, comparable=False` 且 Gate 为 `None`。

### 风险和停止条件

- **需要计划外文件**：预算已用满 **13**（用户 2026-08-02 批准由 12 扩到 13，见 `size_exception`），立即停止并回报，不擅自扩 `allowed_paths`。

- **超过文件预算**：`verify-task` 当场红；停止回报。
- **核心不变量无法证明**：若「五节互不掩盖」无法用机器断言表达，立即 `RETURN_TO_DESIGN`。
