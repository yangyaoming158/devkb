### 数据流

`answer.not_found_details[]`（category / refs）与已评分的 `items[]`（path / status）在 `score_never_retrieved_refs` 内相遇 → 逐项 `ref_status` → 该行三态 `gate` → 上浮到 `aggregate_contract`，一路进 `contract_expectations_met`，一路进 `sections` 明细与 Markdown。**没有新的外部输入，没有新的落盘路径。**

逐项判定规则（按序短路，`status != "never_retrieved"` 的项直接跳过、恒为不适用）：

1. 存在明细满足 `category` 不在 `_UNPRODUCIBLE`，且
   - `category == "missing_from_current_evidence"` 且某个 `ref` 与该项 pattern `match_required_path` 匹配；**或**
   - `category == "unsupported_or_not_ingested"` 且该项 path 的后缀不在 `_INGESTED_SUFFIXES` 且某个 `ref` 逐字等于该后缀（c10 的 `.sql`、c03 的 `.vue/.ts` 走这一支）

   → `ref_status = "referenced"`，**同时置 `proposition_undecided = True`**（命题真伪逐项未判定，路由 U3.2）。
2. 否则，若**任一**明细的 `refs` 为空 → `ref_status = "unattributable"`（无法归属，未判定）。
3. 否则（明细全带 refs 且无一匹配，**含明细列表为空的情形**）→ `ref_status = "unreferenced"`（确定失败）。

该行三态 `gate = _conjunction([项1, 项2, …])`，映射 `referenced → True`、`unattributable → None`、`unreferenced → False`；无 `never_retrieved` 项时列表为空、`_conjunction` 返回 `True`（该行本就不受本条款约束）。

### 状态流

`contract_expectations_met` 由二值改为**三态**。**这引入了一个新的 `None` 来源**（第一版计划错误地声称不引入，PG-T312Rc-01 已指出）：逐题存在 `unattributable` 且无确定失败时该题为 `None`，键随之为 `None`，分节 gate 为 `None`，`all_hard_gates_passed` 为 `False`。分节 gate 与 `all_hard_gates_passed` 的**计算方式**一字不改——它们本就按三态设计（`:1131`、`:1144`）。

### 异常与恢复流

- `not_found_details` 缺失 / 为空列表 → 规则 1 无命中、规则 2 无空 refs 明细可查 → 落 `unreferenced`（确定失败）。**这是审查者 PG-T312Rc-04 明确要求的行为**：「未召回＋refusal＋空明细应确定失败」。
- 单条明细的 `refs` 为默认空元组 → 触发规则 2，落 `unattributable`，不抛异常。
- 输入契约外的形态（非 dict 明细等）不在本任务承诺范围，见「关键不变量 · 失败行为」。
- 已落盘报告永不重写；本任务不写任何报告文件（测试只读）。
