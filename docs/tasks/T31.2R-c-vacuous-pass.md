### 数据流

`answer.not_found_details[]`（category / refs）与 `row.required_evidence[]`（type / path）在 `score_evidence_selection` 内相遇 → 逐 `never_retrieved` 项算 `disclosure` → 逐题结果上浮到 `aggregate_contract` → 一路进 `gates["contract_expectations_met"]`，一路进 `sections` 明细与 Markdown。**没有新的外部输入，没有新的落盘路径。**

逐项判定规则（按序短路）：

1. 该项 `status != "never_retrieved"` → `disclosure = None`（不适用），不进任何桶。
2. 存在明细满足：`category` 不在 `_UNPRODUCIBLE`，且
   - `category == "missing_from_current_evidence"` 且某个 `ref` 与该项 pattern `match_required_path` 匹配；**或**
   - `category == "unsupported_or_not_ingested"` 且该项 path 的后缀不在 `_INGESTED_SUFFIXES` 且某个 `ref` 逐字等于该后缀（c10 的 `.sql`、c03 的 `.vue/.ts` 走这一支）

   → `disclosure = "disclosed"`。
3. 否则，若**任一**明细的 `refs` 为空 → `disclosure = "undecided"`（无法归属）。
4. 否则（明细全带 refs 且无一匹配）→ `disclosure = "undisclosed"`。

### 状态流

`contract_expectations_met` 仍是二值键（`True`/`False`/`None`，`None` 仅在无 contract 行时由 `_all_true(measured=False)` 产生）。新合取项**只从可判定失败取值**：`undecided` 不参与，故不引入新的 `None` 来源。分节 gate 与 `all_hard_gates_passed` 的计算方式一字不改。

### 异常与恢复流

- `not_found_details` 缺失 / 为空列表 → 步骤 2 无命中、步骤 3 无空 refs 明细可查（列表为空即「不存在带空 refs 的明细」）→ 落 `undisclosed`。**这是唯一一处「什么都没披露 = 可判定失败」**，符合条款字面。
- 单条明细缺 `category` 或 `refs` 字段 → `.get()` 取到 `None`，不匹配任何分支，不抛异常。
- 已落盘报告永不重写；本任务不读写任何报告文件（测试除外，只读）。
