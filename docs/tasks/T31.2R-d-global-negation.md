## 任务目标

一个 `full` 终态的回答，**只要正文命中 `NEGATION_MARKERS`（两张现成词表的并集），就必须降为 `partial`**；降级后它自动获得两段确定性能力边界文案（静态摄取覆盖披露 + 已验证范围句），于是 `global_negation_honest` 的 `disclosure_present` 与 `mode_matches` 两项同时成立。

### 冻结的 warning 文案（前审 `PG-T312Rd-02`）

逐字冻结为：

```
finalize: full 正文命中否定标记（{命中的标记，顿号分隔}），保守降级 partial
```

只陈述**两件可证的事**：命中了哪些标记、据此保守降级。**不得**出现「仓库级否定」「虚假断言」「已判定」「不实」等把封闭表匹配说成语义判定的措辞——U1/U2 对这批词做否定断言。

### 为什么不加词，而是换判定方向

`_REPO_LEVEL_NEGATION` 是**用来产生断言**的表：命中它就把某条缺口降级为 `unverifiable_assertion`，等于说「我判定这是仓库级断言」。这种表加得再长也**证不出穷尽**——T31.2R-b 正因如此把一个硬键降成了报告项。

本任务反过来用：宽表只用来**否决 `full`**。误报的代价是「本可以 `full` 的题变成 `partial`」——方向保守，**不产生任何虚假断言**；漏报（表外措辞）由 U3 当场登记为已知边界，不假装拦住了。两者都不需要「这张表是穷尽的」这个证不出的前提。

### 数据流

`answer`（generate 正文）→ `finalize_consistency` 第三条规则 → mode 由 `full` 降 `partial` → `nodes.py:1490-1493` 追加覆盖披露与已验证范围句 → `:1507-1508` 保留 `final_not_found_details` → 评测侧 `disclosure_present` 与 `mode_matches` 同时成立。**无新外部输入、无新 LLM 调用、无新落盘路径。**

### 状态流

`finalize_consistency` 的输入域是三态。新增的唯一转换是 `full → partial`，经由既有 `min(..., key=_MODE_RANK)`，与另外两条降级规则同源。

`policy_refusal` **在本函数的论域之外**：它由 `policy_refuse` 独立节点交付（`nodes.py:972`），该节点的 docstring 把「不经过 finalize」写成拓扑事实，并把 `_MODE_RANK` 缺第四键导致的 KeyError 当作结构性保证。本任务**保持**这个结构，不测它、不改它——第一版把它列进 U5/U6 的组合是错的（前审 `PG-T312Rd-01`）。**第二版的 U10 又以另一种形式犯了同一个错**（「对每个 succeeded 行调用」未排除 `policy_refusal`，而落盘报告里 `c13` / `e07` 正是该终态），第二轮前审指出后改为按 mode 分流。
