# Task Packet：T28.1 refusal/partial 附静态摄取覆盖披露

## 任务目标

**一句可观察结果**：`final_mode ∈ {refusal, partial}` 的每一个回答，正文都带一段**逐字冻结、与问题无关**的摄取覆盖披露，说明**自动摄取管线**支持哪些后缀、不支持哪些，并逐字声明「不足以据此确认仓库是否包含此类文件」；位置按终态**唯一确定**——

- `refusal`：披露是正文的**最后一段**（`answer.endswith(披露)`）；
- `partial`：披露**紧邻 T26.1 范围句之前**，范围句仍是最后一段（`answer.endswith(范围句)`，T26.1 合同不变）；
- `full` 与 `policy_refusal`：**一律不附**。

这段文案使 c03/e05 型回答里的「.vue/.ts 没有证据」可被用户读成**格式可能未摄取**而不是**仓库确实无源码**——而这个区分在 P1.5 只能靠静态能力披露达成（仓库级普查需 inventory，属 P1.6）。

## 背景与当前问题

- **当前行为**：`src/devkb/agent/not_found.py:257-259` 已有 `coverage_disclosure()`，但**在 `src/` 内零调用**（`grep -rn coverage_disclosure src/` 只有定义处；唯一引用方是 `tests/unit/test_agent_not_found.py:29,167`）。也就是说，覆盖披露目前只是一个**被测试覆盖但从未交付给用户**的函数。
- **T23 已有的、不能替代本任务的东西**：`not_found.py:423-427` 的 `static_suffix_rule` 子句会给**被判为 `unsupported_or_not_ingested` 的那一条缺口**追加「…不在当前摄取范围、未纳入本项目索引…」。它是**逐条、条件触发**的：只有当缺口文本自身命中显式后缀 / 隐藏文件 / `TERM_SUFFIX_HINTS` 九条封闭技术词时才出现。缺口文本没命中（模型换个说法、解析没产出带类型标签的确定性说明）时，用户看到的就只有「未找到 X」——**无从判断这是召回失败还是格式根本不在摄取范围**。T28 要补的正是这条静态兜底：与本题命中与否无关，只要 refusal/partial 就披露项目的摄取边界。
- **规格与判据要求**：《P1.5实现规格》§10 逐字「`refusal`/`partial` 附带**静态摄取覆盖披露**：说明本项目摄取哪些后缀、不摄取哪些，使『格式未摄取』可与『仓库确实无源码』区分」「这是静态能力披露，不做逐题语言/意图推断（那需要更完整的语言与结构支持，属 P1.6）」；《P1.5任务清单》T28.1 判据逐字「拒答/部分回答说明本项目摄取/不摄取的后缀…披露文案有单测」；《Evaluation-v1.5》§2 已冻结 c03 的 P1.5 契约预期为「`unsupported_or_not_ingested` + **静态摄取覆盖披露**：说明 .vue/.ts 不在摄取范围、当前无法确认仓库是否包含此类文件（条件式），不得表述为『仓库无源码』」，§5.1 第 7 条与《P1.5实现规格》§15 第 7 条同为 Gate 项。

### 数据流

`ingest.pipeline.SUPPORTED_SUFFIXES`（管线常量）+ `not_found.UNINGESTED_EXAMPLES`（封闭示例表）→ `coverage_disclosure()` 纯函数渲染 → `finalize` 按 mode 拼接进 `final_answer` → `build_answer()` 原样落 `answer_text` → API/CLI/run 持久化。**没有任何分支读取问题文本、证据、documents 表或 project 数据**（这就是「静态」的机器可检形式）。

### 状态流

`finalize_consistency` 定稿 mode →（mode 分支）refusal：`_refusal_text(not_found) + 披露`；partial：`正文 + layer_note + config_note + 披露 + verified_scope_note`；full：`正文 + layer_note + config_note`（不附）。**冻结顺序**：披露在三段确定性文案之后、范围句之前——T26.1 合同「范围句必须是 partial 正文的最后一段」因此不被破坏（G2 逐字断言 `endswith(范围句)`）。

**G7 定位规则**（PG-T281-02）：三方比对的「第三方」= 从图执行的实际正文里**按终态切出**的披露段落，切法唯一确定——
- `refusal`：`answer[answer.index(T281_PREFIX):]`，且额外断言 `answer.endswith(披露)`；
- `partial`：`answer[answer.index(T281_PREFIX):answer.index(T261_PREFIX)]`，且额外断言 `answer.endswith(范围句)`、`answer.index(T281_PREFIX) < answer.index(T261_PREFIX)`；
- 两者都先断言 `answer.count(T281_PREFIX) == 1`（切片唯一）。切出的字符串与 `coverage_disclosure()`、与 packet 围栏三方逐字节相等。

### 异常与恢复流

无异常路径：`coverage_disclosure()` 是无参纯函数，只做 `frozenset` 排序与字符串拼接，不抛异常、不做 I/O。唯一的退化形态是「示例表为空」（若将来把所有示例后缀都纳入摄取范围）——此时省略示例枚举子句、保留其余三句，且 U3 会**先于**该退化转红，逼迫同批更新示例表。
