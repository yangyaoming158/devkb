## 任务目标

### 表 D · 载体分档与插值方言（`carrier_of` 用；输入只有 `rel_path`）

| 档 | 判据（在 `classify_path` 结果之上） | 插值方言 | 参与强制条件维度 |
|---|---|---|---|
| `compose` | `production_config` ∧ basename 含 `docker-compose` 或 ∈ {`compose.yml`,`compose.yaml`} | Compose | 是 |
| `app_config` | `production_config` ∧ 非 compose ∧ ext ∈ {`.yml`,`.yaml`,`.properties`,`.toml`} | Spring | 是 |
| `env_file` | `production_config` ∧ basename == `.env` 或以 `.env.` 开头 | **不判定** | 是（仅注解/关键词维度） |
| `source` | `production_source` | Spring | 是 |
| `other` | 其余全部（文档/测试/迁移/前端/…） | 不判定 | **否**，计入"文档或测试类引用"披露 |

**方言分立是必需的，不是修饰**：Compose 的 `${VAR:?err}` 表示"未设置或为空即报错"，而 Spring 的 `${VAR:xxx}` 里冒号后**整段都是默认值**。同一串字符在两个载体里语义相反，只做一套解析必然在其中一侧产生错误结论——这正是判据第 2 句要防的病。

### 表 E · 五维检出判据（闭合；对**屏蔽后**的片段逐行扫描）

| 维度 | 检出条件（全部闭合、可逐字复算） |
|---|---|
| `scope` | **不做检出判定**——只按表 D 报告每条交付引用的载体档位与条数，并固定声明"本阶段不判定某条配置在某个启动路径下最终是否生效"。 |
| `fallback` | `compose` 档：`${VAR:-…}` / `${VAR-…}`；`app_config`/`source` 档：`${VAR:…}` 且冒号后首字符**不是** `?`。 |
| `required·non-empty` | `compose` 档：`${VAR:?…}`（要求已设置且非空）或 `${VAR?…}`（要求已设置）；任意参与档：非空注解 `@NotBlank` / `@NotEmpty` / `@NotNull`。 |
| `length·strength` | `@Size` / `@Length` / `@Min` / `@Max` / `@Pattern` / `@Digits`；或同一行内 `.length()` 后出现比较运算符（`<` `>` `<=` `>=` `==` `!=`）。 |
| `runtime-validation` | `@Validated` / `@Valid`；`Assert.notNull` / `Assert.hasText` / `Assert.isTrue`；`throw new IllegalStateException` / `throw new IllegalArgumentException`。 |

**`required·non-empty` 与 `runtime-validation` 必须分立**：`@NotBlank` 只是**声明**，Spring 要 `@Validated`/`@Valid` 才会**触发** Bean Validation。二者合并会让"注解写了但没有触发器"这一真实状态（案例八 §11.3 逐字："`JwtProperties` 没有 Bean Validation 或启动时校验"）不可见。

**`@NotBlank` 归入 `required·non-empty` 而非 `length·strength`**：它约束"非空"，不约束长度或形态——合并即复现"非空 ⇒ 强度"的原始错误。

### 屏蔽规则（`mask_advisory`，判据第 2 句的**结构性**执行点）

对参与档的片段，在做表 E 的**关键词扫描**之前依序删除：

1. `/* … */` 块注释（非贪婪，跨行）；
2. 行内 `//` 到行尾——但 `//` 紧跟在 `:` 之后时不删（避免吃掉 `http://`）；

### 异常与恢复流

- `visible_citations` 为空 → 整段省略，不抛异常、不改判终态。
- `evidence_by_id` 取不到某个 `evidence_id`（`visible_citations` 的构造已保证可取，属理论不可达）→ 跳过该行，fail-closed，不猜测内容。
- 纯函数无 I/O；空串内容 → 各维度均"未检出"，载体档位仍按路径产出。
- 畸形插值（`${` 无闭合 `}`）→ 正则不匹配，不计入任何维度，也不报错。

- **如果超过文件预算**：8 个已含全部预期改动（前审后由 7 增至 8，仅为 PG-T263-02 的 backlog 登记），超即停止拆分。
