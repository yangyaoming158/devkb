### 冻结的 Markdown 文案

以下两行**逐字冻结**，实现与测试都不得改写：

```
- generate 归因：未执行 {a} 题、交付 {b} 题、回落冻结默认值 {c} 题（不合规输出 {d}、请求失败 {e}、预算耗尽 {f}、其他 {g} 次）
- 「召回却未引用」按 generate 归因分：未执行 {h} 题、交付 {i} 题、回落 {j} 题、不一致 {k} 题——**归因不改变任何 Gate 判定**
```

**禁用措辞**（D1 断言**只在这两条新增行内**零命中）：`通过`、`达标`、`合格`、`无问题`、`已修复`、`可豁免`、`不算失败`、`非系统缺陷`。理由：generate 失败**是**可靠性缺陷，归因只说明它属于哪一类，不为它开脱。

> **扫描面为什么不是全篇**（前审 `PG-T312Re-04`，已关闭）：`render_contract_markdown` 的固定输出里已有「`None`/未判定不通过——方向 fail-closed」（`eval_contract.py:1331`），含子串「通过」。那句是**诚实的 fail-closed 说明**；全篇扫描会让 D1 必红，而唯一的「修法」是改写一句本来正确的旧文案去迁就新测试。**该句零改动。**

### 数据流

`answer` + `trace` → `score_generation` → 行级 `generation` 子块 → `aggregate_contract` 逐行读 `row["generation"]["status"]` 与既有 `row["evidence_selection"]["retrieved_not_cited"]` → `sections.evidence_selection` 两个新字段 → Markdown 两行。**没有任何一条数据流进 `gates` 字典**（这正是 C1 遍历值域所断言的）。

### 状态流

```
executed       = any(step["node"] == "generate" for step in trace["steps"])
fell_back_seen = any(code.endswith(DEFAULT_APPLIED_SUFFIX)
                     for node == "generate" 的 warning_details)

executed=True  ∧  fell_back_seen → status="fell_back"     fell_back=True
executed=True  ∧ ¬fell_back_seen → status="delivered"     fell_back=False
executed=False ∧ ¬fell_back_seen → status="not_executed"  fell_back=None
executed=False ∧  fell_back_seen → status="inconsistent"  fell_back=None   ← 结构上不可能
```

`outcome_kinds` 只统计**非** `default_applied` 的 generate warning，按 code 尾段前缀匹配四个封闭类别。

### 异常与恢复流

- `trace["steps"]` 缺失 → 直接下标 `KeyError`，**fail loud**（与 R-c 的 `never_retrieved_ref_gate` 同一设计：缺来源要当场炸，不能静默变成「未执行」）。既有 `assemble_row:1590` 已在同一行为下运行。
- `answer` 无 `warning_details` → `.get(...) or []`，与 `score_warning_ledger:854` 一致。
- 未登记 code → `other`，计数照记，**不猜成因**。
- `inconsistent` 不抛异常：它是**报告项**，抛异常会让一整轮评测中断，代价与收益不匹配；B2 断言它可被构造且落 `None`。
