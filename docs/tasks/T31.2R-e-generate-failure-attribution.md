### 冻结的 Markdown 文案

以下两行**逐字冻结**，实现与测试都不得改写：

```
- generate 归因：未执行 {a} 题、交付 {b} 题、回落冻结默认值 {c} 题（不合规输出 {d}、请求失败 {e}、预算耗尽 {f}、其他 {g} 次）
- 「召回却未引用」按 generate 归因分：未执行 {h} 题、交付 {i} 题、回落 {j} 题、不一致 {k} 题——**归因不改变任何 Gate 判定**
```

**禁用措辞**（U11 断言**只在这两条新增行内**零命中）：`通过`、`达标`、`合格`、`无问题`、`已修复`、`可豁免`、`不算失败`、`非系统缺陷`。理由：generate 失败**是**可靠性缺陷，归因只说明它属于哪一类，不为它开脱。

> **扫描面为什么不是全篇**（前审 `PG-T312Re-04`）：`render_contract_markdown` 的固定输出里已有「`None`/未判定不通过——方向 fail-closed」（`eval_contract.py:1331`），含子串「通过」。那句是**诚实的 fail-closed 说明**，不是开脱；全篇扫描会让 U11 必红，而唯一的「修法」是改写一句本来正确的旧文案去迁就新测试——那正是本项目反复禁止的方向。**该句零改动。**

### 数据流

`answer`（Answer JSON）+ `trace`（`get_run_trace` 的只读装配）→ `score_generation` → 行级 `generation` 子块 → `aggregate_contract` 逐行读 `row["generation"]["status"]` 与既有 `row["evidence_selection"]["retrieved_not_cited"]` → `sections.evidence_selection` 两个新字段 → Markdown 两行。**没有任何一条数据流进 `gates` 字典。**

### 状态流

```
executed = any(step["node"] == "generate" for step in trace["steps"])
fell_back_seen = any(code endswith DEFAULT_APPLIED_SUFFIX for node=="generate" 的 warning_details)

executed=False ∧ ¬fell_back_seen → status="not_executed"  fell_back=None
executed=True  ∧  fell_back_seen → status="fell_back"     fell_back=True
executed=True  ∧ ¬fell_back_seen → status="delivered"     fell_back=False
executed=False ∧  fell_back_seen → status="inconsistent"  fell_back=None   ← 结构上不可能
```

### 异常与恢复流

- `trace["steps"]` 缺失 → 直接下标 `KeyError`，**fail loud**（与 R-c 的 `never_retrieved_ref_gate` 同一设计：缺来源要当场炸，不能静默变成"未执行"）。既有 `assemble_row:1590` 已经在同一行为下运行。
- `answer` 无 `warning_details` → `.get("warning_details") or []`，与 `score_warning_ledger:856` 既有写法一致；空表意味着"没有 generate 的失败 warning"，落 `delivered` 或 `not_executed`，由 `executed` 决定。
- 未登记 code → `other`，计数照记，**不猜成因**。
- `inconsistent` 不抛异常：它是**报告项**，抛异常会让一整轮评测中断，代价与收益不匹配；U9 断言它可被构造且落 `None`。

## 冻结测试

> **输入来源纪律：落盘种子 + 明示的最小变换 + 明确标注的合成部分。**
>
> 第一版写「全部逐字派生」，第一轮前审 `PG-T312Re-02` 指出与 U5/U6/U9 的「构造」自相矛盾；第二版改成「种子 + 变换」但**仍然错**——第二轮 `PG-T312Re-02` 实测证明 U6 的种子 `c01` 的 `retrieved_not_cited` 是**空的**，用它根本产不出 U6 要的前提。本版按 `RETURN_TO_DESIGN` 回到 Stage 2 重新冻结，**每条输入的真实性等级逐项标注**。
>
> ### 三个真实性等级（本 packet 全程使用）
>
> - **【落盘】** —— 字段逐字来自落盘报告，零变换。
> - **【最小变换】** —— 落盘种子 + 本表写明的**单一**变换；未列出的字段与种子深比较相等。
> - **【合成】** —— 无落盘实例，只能手工构造。**必须写明为什么没有落盘实例。**
>
> ### `trace` 一律是合成的（前审第二轮结论）
>
> 落盘报告只存已评分的行，**不存轨迹**。因此本任务所有 `trace` 都是合成的，分两种：
>
> - **T1 节点轨迹**：从落盘 `answer["trace_summary"]` 的节点历史切出节点名 → `{"steps": [{"node": …}]}`。只做字符串切分。
> - **T2 带证据的轨迹**：T1 之上给 retrieve 步补 `output_summary`，`rel_paths` 取自同一落盘行 `evidence_selection.items` 中 `status == "retrieved_not_cited"` 的 `path`；复用既有夹具 `_retrieve_step`（`tests/unit/test_eval_contract.py:109-120`）。
>
> **T2 是合成见证，不是恢复出的真实路径**（前审第二轮）：生产判定是 `any(match_required_path(path, pattern) …)`（`eval_contract.py:437-440`），而非通配 pattern 走 `path_matches_token`，带 `/` 时判 `rel_path == token or rel_path.endswith("/" + token)`（`evidence_types.py:877-878`）。把 pattern 原样当 rel_path **满足**该谓词，但真实检索到的路径可能是它的任意前缀扩展。**T2 只保证复现出同样的评分状态，不声称复现了真实路径身份。**已在「判据可证边界」冻结为第四条「推不出」。
>
> **为什么必须有 T2**：`evidence_paths_from_trace`（`:316-325`）**只**从 `node == "retrieve"` 的 `output_summary` 取路径。T1 会让 `evidence_paths` 为空 → 每个必需项都落 `never_retrieved` → **永远产不出 `retrieved_not_cited`**。
>
> **c12 排除在所有 `retrieved_not_cited` 用例之外**：其必需项是通配 `…/web/*Controller.java`，落盘行存的是 pattern，`fnmatchcase` 下 pattern 自身**不匹配自身**（`*` 不匹配字面 `*`），T2 对它不成立。宁可少一例，不手编假路径。
