**求值方式（第三轮设计修订）：四态按该 chunk 在本 run 中到达过的**最后一个阶段**归属，是一条带**显式退出**的阶段优先链**（阶段序：交付引用 ＞ 交给模型 ＞ 保留裁剪 ＞ 通道候选 ＞ 未召回）。逐条求值，命中即归属、不再参与后续判定：

```text
E0  在终态证据集且**已被交付引用**            → 退出四态（成功交付，不是失败归属）
①   在终态证据集且 ∈ evidence_usage.unused    → 已给模型但未采用
E1  进入过任一轮 retention_input 但不在终态证据集：
      ②   在其被淘汰那一轮，位次劣于该轮**全部**保留项 → 低排名被截断
      第五态 存在位次劣于它的保留项                     → 被锚点保留策略挤出（退出四态）
③   从未进入 retention_input，但在任一轮 candidates 中且该轮 outcome=truncated_after_fusion
                                              → 被融合淘汰
④   **两轮候选并集**均未出现，且两轮 candidates_truncated 均为 false → 未召回
    （任一轮 truncated 为 true 时只能降级为"未观测"，不得归入四态）
```

四态因此**两两不交**（每个 chunk 至多命中一条，且 E0／第五态显式退出）。**它们不是对语料的划分**：成功交付的证据（E0）与第五态都不属于四态，四态只是 m15 关心的**失败归属**的互斥分类——本行不得写成"并集覆盖语料"。

反过来，若把四条判据当作**互相独立**的阶段事件谓词求值，同一 chunk 会同时落进两个桶——例如上一轮被选中、以 carried 身份留在证据集、本轮未被重新选中的 chunk，既是"本轮融合淘汰"又是"已给模型但未采用"；此时正确答案是后者（它到达的最后阶段是"交给了模型"），前者只是它路上的一个事件。

| m15 情形 | 判据（自后向前，命中即归属，不再参与后续判定） | 依据 |
|---|---|---|
| ①**已给模型但未采用** | 在终态证据集内（`evidence_id` ∈ generate step 的 `input_summary["evidence_ids"]`）且该 `evidence_id` ∈ finalize `evidence_usage["unused"]`；**已被交付引用的（`cited`）在 E0 退出，不进四态** | 前者是"交给模型"的权威账本（节点入参本身），后者是交付引用的补集。它到达的阶段最靠后，故最先判定 |
| ②**低排名被截断** | 不在终态证据集，但进入过某轮 `retention_input` 并出现在该轮 `eliminated`，**且**在该轮 `retention_input` 中的位次劣于该轮**全部**被保留证据（同摘要 `evidences`）的位次 | `retention_input` 就是 `plan_retention` 内部用于定名次的 `[*fresh_ids, *carried_ids]`（`aspects.py:415` 的 `rank`）。"位次劣于所有保留项"= 它确实是按序被截掉的末尾，与保留资格无关 |
| ③**被融合淘汰** | **从未**进入任何一轮 `retention_input`，但在某轮 `candidates` 中且该轮 `outcome == "truncated_after_fusion"` | 进了通道候选，但 RRF 完整融合序名次 > `top_k`，因此从未进入跨轮合并 |
| ④**未召回** | 以上都不命中，且该 chunk 在**两轮候选并集**中都没有记录，且两轮 `candidates_truncated` 均为 `false` | 候选记录**穷举**了每轮每条子查询 vector 通道返回的全部结果（通道 N == `top_k`，记录逐条不丢）；截断发生时该穷举性不再成立，只能说"未观测" |

**第五态（可观测，但不属 m15 四态，不得与"低排名被截断"混用）**——**被锚点保留策略挤出**：与②同属"走到保留裁剪阶段后在此出局"，区别只在原因——不在终态证据集、∈ `eliminated`，**且**存在位次**劣于**它的被保留证据。成因是 `plan_retention` 的保留资格先于排名取位（`aspects.py:425-437`：`required_reps` → 新证据里的 `diagnostic_reps` → 补检 floor → 其余按 `rank`），**低排名锚点可以挤掉高排名非锚点**。此时淘汰原因是资格而非名次，必须单列。

- 能证明：上表四条谓词两两互斥、可对任一 chunk_id 逐条求值；`vector_rank`/`vector_score`/`fused_rank`/`fused_score` 是实测值，可复算 RRF（`fused_score = Σ 1/(60+vector_rank)`）。
- 推不出：
  1. **"未召回"推不出"仓库里没有它"或"检索器判定它不相关"**——只证明**两轮**各子查询的 vector 通道都没有返回它（且两轮候选账本都未截断）。
  2. **"未召回"内部不再细分"通道 top-N 低排名截断"与"完全不匹配"**——通道 N == final `top_k`，N 之外的内容根本没有被观测；扩大 N 会改变融合成员（见「非目标」），故本阶段结构性不可分。**这不影响 m15 四态可判定性**：m15 的"低排名被截断"由跨轮容量截断这一可观测事件承载。
  3. **`truncated_after_fusion` 推不出"该证据与问题无关"**——只证明名次落在 `top_k` 之外。
  4. **`outcome == "selected"` 推不出"进了交给模型的证据集"**——其后还有跨轮保留裁剪；权威账本是 generate step 的 `evidence_ids`。
  5. **`candidates_truncated == True` 后推不出任何"全部候选"的穷举结论**（也因此，"未召回"判据只在 `candidates_truncated == False` 时成立——截断时必须降级为"未观测"）。
  6. **单看某一个阶段事件推不出该 chunk 的归属**（第三轮设计修订）：同一 chunk 可以在路上留下多个阶段事件（本轮候选里被融合淘汰、同时又因 carried 身份留在证据集）。四态是"**到达的最后一个阶段**"，必须按上面那条带显式退出的优先链归属；把四条判据当独立谓词并集求值会得到重叠的桶，那不是四态本身重叠，而是求值方式错了。
  7. **四态推不出对语料的划分**：成功交付的证据（E0）与第五态都显式退出四态，故"两两不交"成立而"并集覆盖语料"不成立——四态只是 m15 关心的失败归属分类，不得据它对未归入的 chunk 下任何结论。
  8. **`eliminated[].reason` 本身推不出"低排名"**（前审 PG-T301-01 第二轮）：`aspects.py:456-461` 的 `reason` 只区分"被淘汰项还带着未被保留项覆盖的方面"（`aspect_anchor_capacity`）与"纯容量"（`capacity_limit`），**两者都可能发生在高排名非锚点被低排名锚点挤出的情形**。"低排名被截断"必须由 `retention_input` 的**位次关系**判定，不得由 `reason` 推断。
- 对应 fail-closed 负例：U5、U7、**U16**、B1、B2、H1、I1-c、**I1-d**。

**J2 refine term 来源 `∈ {default, user_question, retrieved_evidence, unattributed}`**

- 定义（**纯字面、非因果**）：`default` = 本次 refine 走了冻结默认值（`refine_failed == True`）；`user_question` = 该 query 规范化后是用户问题规范化文本的子串；`retrieved_evidence` = 该 query 规范化后是某条当前证据的 `rel_path`/`title_path`/`content` 规范化文本的子串；三者都不成立 → `unattributed`。优先级即上述顺序。"term"在本仓库的产出单元是**一条 refine query**（`RefineOutput.queries` 的每一项，`state.py:117-123`）。
- 能证明：该 term 是否**逐字**可追溯到用户问题或已检证据；本次 refine 是否走了冻结默认值。
- 推不出：**推不出因果**——`user_question` 不证明"模型据问题生成"，只证明字面包含；`unattributed` 不证明该 query 更差或凭空捏造，只证明**无法逐字追溯**（模型重写的正常结果）。**本任务不设 hint 归因类目**（`uncovered_hints` 与 term 的字面重合同样不能证明因果）。
- 对应 fail-closed 负例：U10（含"与 uncovered hint 逐字重合仍不得标为 hint 来源"）、U11。

**J3 `evidence_usage`（已给模型但未采用）**

- 能证明：**在 generate 实际执行过的前提下**（`generate_calls > 0`），该 `evidence_id` 进入了 generate 的证据集，但不在最终交付引用（保留 claim 的 `evidence_ids` ∪ 终态正文中通过 L0 的 `[E#]`）之中——与用户在 Answer `citations` 里看到的是同一套账本。
- 推不出：
  1. 推不出"模型读过并判定其无关"——未被引用可能因 claim 被移除后正文重建、generate 降级为确定性文案、模型遗漏，或终态本就是 refusal。
  2. **generate 从未执行时推不出任何"已给模型"结论**（`route_after_evaluate`/`route_after_refine` 存在证据非空却直接进 finalize 的分支）：此时记 `generate_executed: false` 且 `given`/`cited`/`unused` **三者全空**，绝不把"未交给模型"写成"已给模型但未采用"。
- 对应 fail-closed 负例：U13、U14、U15。

**J4 `not_found_details` 摘要**

- 能证明：终态每条缺口的来源标签（`source`）与 T23 的事实校验依据（`category`/`basis`/`refs`），逐位对齐同一摘要的 `not_found`。
- 推不出：
  1. 不新增任何判定——只转载 T23 已产出的 `NotFoundDetail` 的**分类与依据四字段**，不重新分类、不重新校验；T23 原有的"不断言仓库有无该文件"边界原样继承。
  2. **摘要不是权威载体**：它按 `MAX_SUMMARY_ITEMS`(8) 截断，且**不含 `text`/`original_text`**（避免自由文本重复落盘，见「零新增自由文本」）。权威全量在 Answer JSON 的 `not_found_details`（`agent/answer.py:112-122`，含 `text` 与 `original_text`）；**不得据摘要作条数穷举或原文比对**。
- 对应 fail-closed 负例：U12、H2。

**J5 有界性**

- 能证明：记录条数恒 ≤ 冻结常量；超限置 `candidates_truncated=True`。
- 推不出：见 J1-5（截断后不得作穷举结论）。
- 对应 fail-closed 负例：B1、B2。

### 数据流

```text
make_pg_retriever._retrieve(project_id, queries)
  per_query[(qi, hits)]  qi = query 在 queries 元组中的首次出现下标（去重后仍指回原下标）
  fused_all = rrf_fuse(rankings)        # 完整序（既有函数，未改）
  fused     = fused_all[:top_k]         # 既有裁剪，返回值逐字节不变
  └─ recorder.record_retrieval_candidates(*build_candidate_records(per_query, fused_all, top_k=top_k))
        │ 每条 = (query_index, chunk_id, rel_path, start_line, end_line,
        │         vector_rank, vector_score, fused_score, fused_rank, outcome)
        ▼  TraceRecorder._pending_output  →（finish_step drain）→ StepRecord.output_summary
        ▼  _persist_trace → agent_steps.output_summary (JSONB) → get_run_trace()

nodes.retrieve
  merged = {fresh 优先, setdefault 去重}     # 既有代码，插入序 == plan_retention 的 rank 序
  plan   = plan_retention(..., limit=max_evidences)
  └─ recorder.record_retention_input(list(merged), limit=max_evidences)
        → output_summary["retention_input"] / ["retention_limit"]
        → 与同摘要 evidences(保留) / eliminated(淘汰) 三者合起来，使"低排名被截断"
          可由**位次关系**判定，而不是由 eliminated[].reason 推断（PG-T301-01）
```

### 状态流

`AgentState` 零变化。诊断事实的生命周期完全在 `TraceRecorder` 内：生产者 push 到 `_pending_output` → 当前 step 的 `finish_step` drain 并清空 → `StepRecord` 不可变 → `_persist_trace` 落库。与既有 `_pending_llm`/`_pending_tools` 同一模式（`trace.py:76` 已声明该模式依赖"图顺序执行"这一拓扑事实）。

### 异常与恢复流

- 检索器抛异常（`SQLAlchemyError` 已在 `make_pg_retriever` 内 rollback 后上抛）：候选记录写在融合之后，故**一条都不写**；`retrieve` 节点既有的 `record_tool(status="failed", result_summary=None)` 与 `errors` 降级路径逐字不变。
- 节点内未捕获异常：`_traced` 走 `finish_step(status="failed", output_summary=None)`；pending 若非空（结构上不可能——三处记录都在节点 return 前的最后一步）也会被合并进一个新 dict 并清空，不跨 step 泄漏。
- **generate 从未执行**（证据非空但预算耗尽直接进 finalize）：`evidence_usage` 记 `generate_executed=false` + 三个空列表，不产生任何"已给模型"断言（J3-2）。
- `recorder=None`（离线图测试）：三个记录点全部被 `is not None` 短路，`build_candidate_records` 根本不执行——零开销、零行为差异。
- 轨迹落库失败：沿用 `agent/service.py:210-215` 的 rollback + `trace_persist_failed` 日志，run 终态不受影响。

### 风险和停止条件

- **如果需要计划外文件**：停止并回到本门禁。特别是——若"已给模型但未采用"无法与 `build_answer` 的 `citations` 口径对齐而需要改 `agent/answer.py`，视为计划前提被推翻。
- **如果 m15 四态无法各自命中**：先按「尚未证实的假设」调构造参数（语料规模/`top_k`/子查询）。若调参后仍有某一态结构性不可达，**停止并写入《P1.5任务清单》偏差记录等用户裁决**，不得改断言、不得改检索机制来凑。
- **如果规格与代码事实冲突**：停止并写入偏差记录。尤其"是否必须建 0004 迁移"——本计划的裁断是「判据为条件句、本设计不需要建表/加列，故不建」。
- **如果超过文件预算**：停止。10 个文件已含 `docs/backlog.md`，无冗余额度。
- **如果核心不变量无法证明**：若无法在不改检索行为的前提下拿到完整融合序，停止并重新设计——**绝不允许**为了观测而调大 `per_channel_n`/`top_k`。
