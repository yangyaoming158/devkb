# Agent / RAG 前置不变量

仅在任务涉及对应能力时加载。每项必须写出“适用行为 + 测试”，或写明“不适用 + 仓库证据”；不得默认为安全。

## Agent 状态

- 列出 run 与 step 的状态、合法转换和终态。
- 中断、失败、超时、取消、重试和服务重启后的恢复行为可判定。
- 已完成步骤不可被无条件重复执行；恢复点和持久化边界明确。
- 并发更新有条件写入、锁、版本号或其他可证明的冲突策略。

## Tool Calling 与审批

- 参数有明确 schema，后端在执行边界再次校验。
- 工具有超时、错误分类和可追踪的输入/结果。
- 标注只读、低风险写入、高风险写入；高风险操作在批准前不可执行。
- 重试需要幂等键或等价去重机制，明确未知结果时是否允许重试。
- 非法参数、错误工具选择和审批身份不匹配不会进入业务系统。

## 数据一致性

- 数据库写入与外部副作用的顺序、事务边界和部分成功行为明确。
- 重复请求不会产生重复记录或重复外部动作。
- “数据库成功但 Agent 判失败”和“Agent 判成功但写入失败”都有恢复或补偿。
- 事件、任务和资源身份不能只靠易变文本或进程内状态关联。

## RAG

- document、chunk、embedding/vector 的身份和版本关系明确。
- 删除、重建索引、embedding 失败和重试不会留下可检索脏数据。
- 检索在数据源处执行租户/用户权限过滤，不能只在生成后过滤。
- 回答引用可追溯到本次真实检索结果；未检索到证据时不能伪造引用。
- 解析、索引、检索、生成、引用和评测应能独立验证。

## LLM 不确定性

- 结构化输出缺字段、类型错误、语法错误和语义非法分别处理。
- 超时、限流、拒答、空响应和部分流式响应有明确失败行为。
- JSON 合法但违反领域不变量时仍会被拒绝。
- Prompt injection 不能改变系统权限、工具审批或数据访问边界。
- 模型输出不得直接成为高风险副作用；确定性代码负责最终校验。

## 最低测试矩阵

至少覆盖任务适用项：成功、非法状态、重复执行、并发/竞态、越权、审批前执行、外部超时、未知结果重试、部分成功、恢复、解析失败、合法 JSON 的语义错误、检索权限、索引删除/重建与引用一致性。
